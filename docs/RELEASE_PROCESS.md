# Как выпускать обновления KNOPIK TAP

Первый релиз с официальным номером: **1.0.0** (начало журнала изменений).

## Номера версий

- **1.0.1, 1.0.2** — исправления багов, небольшие правки баланса.
- **1.1.0, 1.2.0** — новые предметы, режимы и игровые механики.
- **2.0.0** — крупное переосмысление игры или несовместимые изменения.

Версия интерфейса не равна `SAVE_VERSION` в `app/game-logic.ts`: это отдельная версия формата сохранений.

## Перед каждым релизом

1. Установить следующий номер в `GAME_VERSION` в `app/release-notes.js`.
2. Добавить **в начало** `RELEASES` запись с тем же номером, реальной датой релиза, коротким названием и 2–5 пунктами. Не записывать несделанные функции.
3. Установить тот же номер в `package.json` и корневых полях `package-lock.json` (например, `npm version 1.0.1 --no-git-tag-version`).
4. Поменять `CACHE_NAME` в `public/sw.js`, чтобы обновились офлайн-ресурсы.
5. Проверить `node --test tests/release-notes.test.mjs`, `npm run lint`, `npm run build`. Только затем выпускать обновление.
6. Слить PR и опубликовать игру. **Сама запись в GitHub не обновляет запущенную игру**: необходимо развернуть новую сборку.

Каждый PR, меняющий игровые файлы, должен содержать новый номер и запись в журнале. Проверка GitHub Actions не пропустит релиз без них.

## Что увидит игрок

- После установки новой версии **возвращающийся игрок** видит «Игра обновлена до версии X.Y.Z» с кнопкой «Подробнее».
- Уведомление скрывается только после нажатия «Подробнее» или крестика; выбор запоминается в `localStorage` **отдельно для каждого аккаунта на данном устройстве**.
- Журнал доступен в любой момент через **Настройки → Журнал обновлений**. Все новые записи появляются там автоматически.
- Новым игрокам не показывается уведомление об обновлении посреди первого обучения.
- При блокировке локального хранилища уведомление может появиться повторно после перезапуска. Облачное сохранение ради этого не изменяется.

## Пример новой записи

```js
export const GAME_VERSION = "1.0.1";
export const RELEASES = [
  {
    version: "1.0.1",
    date: "YYYY-MM-DD",
    title: "Небольшое обновление",
    changes: ["Исправлено ...", "Улучшено ..."],
  },
  // Прежние записи не удалять.
];
```

Показывайте изменения, которые действительно вошли в этот выпуск. Не переименовывайте старые релизы задним числом.
