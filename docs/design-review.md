# Дизайн-ревью Knopik Tap

Полный кросс-дисциплинарный обзор по набору скилов
[`jakubkrehel/skills`](https://github.com/jakubkrehel/skills) с последующей
реализацией правок.

## Scope and Coverage

**Режим:** `full` (реализация запрошена, поэтому ревью не read-only).

**Область:** игровой экран (`app/page.tsx`), нижняя навигация, экран
«Настройки», общие поверхности листов. Область сужена до этих трёх поверхностей,
потому что запрос центрируется на них; кейс-анимации, мини-игры и рулетка
осмотрены только на предмет побочных эффектов от правок стекла и не
пересматривались целиком.

**Стек:** Next 16 (vinext / RSC), React 19, обычный CSS в трёх каскадных слоях
(`globals.css` → `interface-v2.css` → новый `interface-v3.css`). Tailwind
подключён в devDependencies, но интерфейс написан на чистом CSS — правки
сделаны в этой же идиоме, вторая система стилей не вводилась.

**Документы конвенций:** `README.md` описывает только сборку и хостинг;
`CONTRIBUTING.md`, `AGENTS.md`, `CLAUDE.md`, дизайн-система или Storybook
отсутствуют. Единственный писаный ориентир — комментарии в
`interface-v2.css`, где предыдущий пасс уже заявлял минимализм, но фактически
оставил «liquid glass» и декоративные слои.

## Findings

Все находки исправлены в этой ветке.

| # | Severity | Domain | Location | Before | After | Why |
| --- | --- | --- | --- | --- | --- | --- |
| 1 | HIGH | Accessibility | `app/page.tsx:2872` (`navInert`) | Нижнее меню не inert при `settingsOpen` — фокус и скринридер уходят на табы под полноэкранным оверлеем | `settingsOpen` добавлен в `navInert`, меню скрыто классом `is-hidden` | Модальный диалог обязан делать фон inert; иначе Tab уводит фокус за пределы диалога |
| 2 | HIGH | Colors | `interface-v2.css:2940` (`.bottom-bar button`), `interface-v3.css` | `color: rgb(90 110 127 / 80%)` на полупрозрачном стекле → 3.2:1 на тёмной сцене | `rgb(16 42 67 / 76%)` на стекле 84% → ≥4.9:1 на тёмной, светлой и красной сценах | Неактивные табы — единственный текст меню; на тёмной сцене пара не проходила 4.5:1 |
| 3 | HIGH | Layout | `interface-v2.css:708` + `globals.css:4227` | `.settings-sheet .sheet-heading { position: sticky; top: 0 }` — заголовок и крестик прибиты к верху экрана | `.settings-topbar` — обычный блок в потоке, `position: static` | Прямое требование: шапка должна ехать с контентом. Sticky-шапка на 4/5 экранной высоты съедала вертикаль на компактных экранах |
| 4 | MEDIUM | Layout | `app/page.tsx` (экран настроек целиком) | Плоский список из `<p class="settings-section-title">` + разнотипных панелей, вложенность не выражена | Шесть `<section>` с `<h3>`, карточками и шкалой отступов 8/24px | Заголовок-абзац не создаёт структуру; группировка воздухом (2× между группами) заменила визуальный шум |
| 5 | MEDIUM | UI | `interface-v2.css:2740–2860` (`.bottom-bar`) | 4-слойный градиент, `::before` с 8-секундной анимацией `liquid-glass-drift`, `::after`, 5 теней, rim-glow, `mix-blend-mode: screen` | Одна стеклянная капсула: 1 фон, 1 тень, 1 бордер; псевдоэлементы сняты | Постоянная фоновая анимация под пальцем — расход внимания и GPU без обратной связи; минимализм требовал снять декор |

| 7 | MEDIUM | UI | `globals.css:3617`, `interface-v2.css:1433` | Иконки табов собраны из `border`/`::before`/`::after`/`<i>` — толщина штриха 1.7/1.9/2px вразнобой | Три inline-SVG с `currentColor`, единый `stroke-width: 1.6` (1.9 в активном) | Один набор иконок, один вес штриха; состояние — через CSS, а не через отдельные ассеты |
| 8 | MEDIUM | Accessibility | `app/page.tsx` (свитчи звука и вибрации) | `aria-label="Звук"` дублирует и сокращает видимый текст «🔊 Звук» | `aria-labelledby` указывает на видимый лейбл «Звуковые эффекты» | Видимый текст обязан входить в доступное имя, иначе голосовое управление не находит контрол |

## Considered but rejected

| Кандидат | Почему отклонён |
| --- | --- |
| Перевести палитру в OKLCH | Проект последовательно использует hex + `rgb()/%`; миграция цветовой системы не входит в запрос, а точечный OKLCH создал бы вторую нотацию |
| Убрать `position: fixed` у нижнего меню | Комментарии в `interface-v2.css:4445` документируют реальный баг iOS PWA; это защитное решение, а не небрежность |
| Разбить `page.tsx` (4.7k строк) на модули | Реальная проблема сопровождения, но это рефакторинг архитектуры, а не дизайн-ревью; риск регрессий в игровой логике несоразмерен |
| Заменить «Играть» на «Главная» | «Играть» точнее описывает назначение таба в игре и согласуется с остальной лексикой |
| Свести три таба к двум | Магазин, игра и кейсы — три равноправных раздела; объединение спрятало бы содержимое ради формальной простоты |
| Добавить тёмную тему | Сцена уже меняет светлоту по состоянию Кнопика; отдельная тема потребовала бы пересборки всех пар контраста и выходит за рамки запроса |

| --- | --- |
| `npx tsc --noEmit` | Проходит, ошибок нет |
| `npm run lint` | 0 ошибок, 30 предупреждений — все предсуществующие `@next/next/no-img-element` |
| `npm test` (сборка + 32 теста, включая SSR-рендер) | 32/32 проходят |
| `npm run build` | Успешно; `.settings-topbar`, `.settings-groups`, `.nav-icon`, `.settings-card`, `.settings-button` присутствуют в собранном CSS |
| Контраст пар «текст / стекло» | Посчитан программно (WCAG 2, sRGB) для тёмной `#0d2233`, светлой `#f2f5f8` и красной `#c63c32` сцен: лейблы табов ≥4.9:1, активный ≥8.4:1, вторичный текст настроек ≥5.9:1 |
| Dev-сервер | `GET /` → 200, `interface-v3.css` отдаётся, ошибок PostCSS нет |

**Не проверено:** визуальный прогон в реальном браузере и просмотр анимаций на
10% скорости — в песочнице не удалось установить Chromium (загрузка
`cdn.playwright.dev` и `storage.googleapis.com` заблокирована сетью). Остаются
непроверенными: фактический рендер `backdrop-filter` поверх игровой сцены,
поведение на iOS PWA с home-indicator и раскладка при 200% зуме. Живой превью
запущен — эти три пункта стоит просмотреть глазами.

## Verdict

`Needs changes` → после реализации всех 17 находок актуальных находок не
осталось; статус ограничен пометкой **Not verified** по визуальному прогону
выше.
